# Changelog — Хасиева Софья · Go Getter 4 Mini App

## 2026-10-10

- The Halloween boot screen now ignores the top cutout on purpose: the artwork stays full-bleed edge to edge and the headline sits where it lands, under the notch or under Telegram's own header if that is where it falls. Only the bottom inset is still respected, so the button stays clear of the home indicator; the catalog, mission and review screens keep their insets untouched. The headline moved up by the 41px that the top inset used to reserve (measured at y=148 instead of 189 on a 390×844 viewport with 59/34 insets, artwork still 0→844). Cache key is now `miso-motion-v14-20261010`.

- The app no longer locks her out when the private bridge is unreachable. Startup now waits 8 s for the first handshake instead of 20, and when it fails the catalog opens for work: the unit card stays enabled (`Start →` / `Continue →`), the status reads "Connection unavailable. Your work is saved on this device. You can keep working; it syncs when the connection returns.", answers are kept in the device copy with the pending marker set, and the next successful save resolves any revision drift through the merge/conflict path. Before this the catalog sat at `Connecting…` with a disabled unit card for as long as the bridge stayed down, which is also what "0 of 7 days complete" looked like from her side of the screen. Cache key is now `miso-motion-v13-20261010`.

- Added a read-only tutor preview, so the tutor can see the learner's side without her device. The app asks the backend for the learner's sheet row instead of the tutor's own: the catalog shows her XP and `N of 7 days complete`, a finished day shows her score, the day summary lists every attempt with its time, and `Review mistakes` walks her errors one at a time with the counter and the content's explanations. It opens either directly with `?preview=1` or from Telegram with `https://t.me/CheckUphw_bot?startapp=preview`. Nothing can be written from that screen: the client keeps its save path closed (its `restored` flag never becomes true and `save()` returns before touching the device) and the backend's new `preview` action has a read branch only — any account that is not the bound tutor is rejected, and the learner's `Progress` row is never written by it. Verified with a stubbed transport: only the `preview` call is ever made and no learner state reaches the tutor's device. Backend published as Personal Tutoring @12 with a `tutoring-ready` read-back; the status row turns lime and reads `Tutor preview · <name> · read only`.
- Tried to read the tutor's workbook to check whether day 4 was lost on the server. Blocked by Google-side restrictions on the clasp OAuth client: the Sheets API is disabled in clasp's own GCP project (`1072944905499`, and this account has no permission to enable it), Drive export is refused for the same client, and the Apps Script Execution API refuses `clasp run`. The tutoring project's HEAD was modified for that attempt and then restored byte-identically — a fresh `clasp pull` compares equal for all four files, no version was created and both deployments are untouched. The in-app preview now answers the day-level question; the raw `Recovery` history still needs a CSV export or an OAuth client in a project where the Sheets API can be enabled.

- A wrong answer now reaches the tutor's sheet immediately in Street Style. It is written into the day's answers as `{correct:false, pending:true, wrong:[her attempt], expected:[the right one], at:[timestamp]}` and pushed straight away, so the tutor's CheckUp arrives while the mistake is fresh; the later correct answer updates that same entry instead of adding a second one for the question, and `firstTry` records that it took two goes. Before this the attempt only existed inside `wrong[]` once she answered correctly, and the backend creates a `Results` row only when `day.answers.length > 0`, so a wrong answer could stay invisible to the tutor indefinitely. Cache key is now `miso-motion-v11-20261010`.
- Tried to read the tutor's workbook directly to check whether day 4 was lost on the server. Blocked by Google-side restrictions on the clasp OAuth client: the Sheets API is disabled in clasp's own GCP project (`1072944905499`, and this account has no permission to enable it), Drive export is refused for the same client, and the Apps Script Execution API refuses `clasp run`. The tutoring project's HEAD was modified for that attempt and then restored byte-identically — a fresh `clasp pull` compares equal for all four files, no version was created and both deployments are untouched. Reading the workbook needs either a CSV export of `Progress`/`Results`/`Recovery` or an OAuth client in a project where the Sheets API can be enabled.

- Reworked what a finished day does, and closed the path that was silently erasing one. A completed entry now reads `N% correct` with a `Try again` control beside it; opening a finished day shows its summary — best score and every attempt with its local time — instead of quietly restarting the mission. `Try again` goes through a mistake review first: one error at a time with a counter (`1/2`), what she answered, the correct version, and the content's own explanation, and only the last error offers `Start a new attempt`. Every run is appended as an attempt with a timestamp (`runs[]`), the day keeps its best score, and the union of both sides survives a merge.
- Fixed the defect that most plausibly explains "she finished 04 Gap Detective and it looks like she did nothing": every day write replaced the whole day object, so answering a single question during a re-run dropped `score`, `completedAt`, `runs` and `drafts` and set `complete:false` — un-completing a finished day on the device and pushing that state to the sheet. All three writers now spread the existing day object, and a finished day can no longer be restarted by tapping it.
- Progress restore merges the sheet state with the device state instead of refusing on a revision mismatch. The old guard threw "Newer progress exists on another device… contact your tutor", left `restored` false, and showed a learner who had finished four days a catalog reading "0 of 7 days complete" with a disabled unit card.
- Removed the learner-facing `Reset progress` control: resetting is the tutor's action, not hers.
- The Telegram BackButton now hides inside `#review-` and `#retry-` routes, like it already did inside `#day-`.
- Cache key is now `miso-motion-v10-20261010`.

- Made the write to the tutor's sheet visible, and closed the browser route for learners. A save bar now rides on the bottom edge of the status row: it fills to ~12% when a change is queued, creeps while the bridge answers, completes in `--signal` lime on confirmation, and turns `--bad` red if the write fails; because it is drawn on the existing border, showing it never shifts the layout, and it is `aria-hidden` since the status text already carries the meaning. A completed question now writes through immediately (`save(true)`) instead of waiting for the 900 ms keystroke debounce, in both Street Style and Grammar Snack. The plain browser link no longer runs a lesson — without Telegram there is no `initData`, and therefore no sheet — so it shows a gate pointing at `@CheckUphw_bot`, while `?qa=1` (or any local server) keeps the practice build available for review. - Fixed the Halloween boot screen on a cold mobile connection. The overlay armed its 2 s auto-close as soon as it was appended, while the background art is a separate 1.4 MB request that only starts at that same moment — on a throttled 1.6 Mbps profile, captured on an emulated iPhone 14, the screen closed with nothing but the dark background and the headline ever visible, so the artwork itself was never seen.
